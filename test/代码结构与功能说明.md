# 代码结构与功能说明

> 本项目由 Express 后台服务 `file-preview-demo/admin-server` 完整迁移而来，接口路径、请求/响应结构与 Express 版保持一致，前端只需切换 baseURL 即可无缝对接。

## 一、项目概述

| 项    | 说明                                                               |
| ---- | ---------------------------------------------------------------- |
| 技术栈  | Spring Boot 3.2.5 + Java 17 + MyBatis-Plus 3.5.5 + MySQL 8.0     |
| 数据库  | `jdbc:mysql://localhost:3306/test`（10 张 `sys_*` 表 + 原有 `user` 表） |
| 默认端口 | 8080                                                             |
| 认证方式 | JWT（HS256）+ 数据库会话表双重校验                                           |
| 密码算法 | scrypt（BouncyCastle，与 Node.js `crypto.scrypt` 格式完全兼容）            |
| 默认账号 | admin / 123456                                                   |

## 三、功能模块与接口清单

### 1. 认证 `/api/v1/auth`

| 方法   | 路径           | 说明                                                       | 权限          |
| ---- | ------------ | -------------------------------------------------------- | ----------- |
| POST | `/login`     | 登录：scrypt 校验 → 签发 JWT（含 jti 会话号）→ 写会话表 + 登录日志 → 更新最后登录信息 | 免登录（生产环境限流） |
| GET  | `/me`        | 当前用户身份（基础信息 + roles + permissions）                       | 登录          |
| GET  | `/menus`     | 当前用户菜单树（admin 全量，其他按角色过滤，仅非按钮）                           | 登录          |
| POST | `/heartbeat` | 刷新会话最后活跃时间                                               | 登录          |
| POST | `/logout`    | 会话标记 LOGOUT                                              | 登录          |

**认证流程**：请求头 `Authorization: Bearer <token>` → JWT 解析（sub/username/roles/jti）→ 查 `sys_user_session` 校验状态：

- `KICKED` → 401 当前账号已被管理员强制下线

- `LOGOUT`/其他非 ACTIVE → 401 登录会话已失效

- `expires_at` 已过期 → 标记 EXPIRED 并返回 401

### 2. 系统管理 `/api/v1/system`

| 模块 | 接口                                                                                                          | 权限标识                                                            |
| -- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 用户 | `GET/POST /users`、`GET/PUT/DELETE /users/{id}`、`PATCH /users/{id}/status`、`POST /users/{id}/reset-password` | `system:user:list/add/edit/delete/change-status/reset-password` |
| 角色 | `GET/POST /roles`、`PUT/DELETE /roles/{id}`、`GET /roles/{id}/menu-ids`、`PUT /roles/{id}/menus`               | `system:role:list/add/edit/delete/permission`                   |
| 菜单 | `GET/POST /menus`、`PUT/DELETE /menus/{id}`                                                                  | `system:menu:list/add/edit/delete`                              |
| 组织 | `GET/POST /orgs`、`PUT/DELETE /orgs/{id}`                                                                    | `system:org:list/add/edit/delete`                               |
| 参数 | `GET/POST /params`、`PUT/DELETE /params/{id}`                                                                | `system:param:list/add/edit/delete`                             |

**业务规则**：

- 用户删除为逻辑删除，禁止删除当前登录用户；新增/修改在事务内同步维护 `sys_user_role` 关联；未填密码默认 `123456`

- 角色删除保护 `admin` 角色；权限分配先清后插 `sys_role_menu`

- 菜单/组织删除前检查是否存在未删除子节点（"请先删除子菜单/下级组织"）；上级不能是自身

- 组织新增/修改自动计算 `ancestors` 祖级路径（如 `1,11`）

- 删除接口的 `{id}` 支持逗号分隔批量（如 `/users/1,2,3`）

- 用户/角色/参数为分页查询（`pageNum`/`pageSize` + 模糊筛选），菜单/组织返回树

### 3. 日志管理 `/api/v1/logs`

| 模块   | 接口                                                                                                             | 权限标识                               |
| ---- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 操作日志 | `GET /operation`（分页）、`DELETE /operation`（body: ids）、`GET /operation/export`（CSV）                               | `log:operation:list/delete/export` |
| 在线用户 | `GET /online`（分页）、`DELETE /online/{sessionId}`、`DELETE /online`（body: sessionIds）、`DELETE /online/expired`（清理） | `log:online:list/kick/clean`       |
| 登录日志 | `GET /login`、`DELETE /login`、`GET /login/export`                                                               | `log:login:list/delete/export`     |

**查询参数约定**（与 Express 一致）：`status` 支持 `成功/失败/1/0`；日期支持 `dateRange=起,止` 或 `startDate/endDate`；操作类型 `type` 支持中文（新增/修改/删除/查询/导出）与英文枚举。CSV 导出带 UTF-8 BOM，上限 10000 条。

**在线会话规则**：ACTIVE + 未过期 + 5 分钟内活跃 才算在线；不能踢自己；清理操作将过期/闲置会话标 EXPIRED、物理删除 30 天前的非活跃会话。

### 4. AI 对话 `/api/v1/ai/chat/stream`（POST，multipart）

- 入参：`message`（文本）、`history`（JSON 数组，≤30 条）、`files`（≤5 个，单个 10MB，总 20MB）

- 文件处理：图片 → `image_url`（base64）、文本类 → `text`、其他 → `file`（base64）

- 出参：`application/x-ndjson` 流式，事件依次为 `{"type":"start"}` → `{"type":"thinking"}`（可选）→ `{"type":"delta","content":...}`（多次）→ `{"type":"done"}`；失败输出 `{"type":"error","message":...}`

- 后端转发至 OpenAI 兼容网关（`app.ai.gateway-base-url`），需登录，无按钮级权限

- 未配置 `app.ai.api-key` 时返回 503

### 5. 其他

| 方法                | 路径                             | 说明                            |
| ----------------- | ------------------------------ | ----------------------------- |
| GET               | `/api/v1/dashboard/statistics` | 用户/角色/菜单数量 + 今日活跃用户数（登录即可）    |
| GET               | `/health`                      | 健康检查 `{status:UP, timestamp}` |
| GET/POST/DELETE 等 | `/api/user/**`、`/hello`        | 【原有演示接口，保留】                   |

## 四、横切机制

### 统一响应

```json
// 成功
{ "code": 0, "message": "操作成功", "data": ... }
// 分页 data
{ "list": [...], "total": 100, "pageNum": 1, "pageSize": 10 }
// 失败
{ "code": "LOGIN_FAILED", "message": "用户名、密码错误或账号已禁用" }
```

### 全局异常（GlobalExceptionHandler）

| 场景             | HTTP | code                              |
| -------------- | ---- | --------------------------------- |
| 参数校验失败         | 400  | VALIDATION\_ERROR（附 details 字段明细） |
| 唯一键冲突          | 409  | DUPLICATE\_DATA                   |
| 路由不存在          | 404  | NOT\_FOUND                        |
| 方法不支持          | 405  | METHOD\_NOT\_ALLOWED              |
| 上传超限           | 413  | PAYLOAD\_TOO\_LARGE               |
| multipart 格式错误 | 400  | INVALID\_MULTIPART                |
| 业务异常           | 按定义  | 按 AppException                    |
| 未知异常           | 500  | INTERNAL\_ERROR（仅服务端日志，不泄露堆栈）     |

### 操作日志（OperationLogFilter）

- 拦截范围：`/api/v1/**` 下的 POST/PUT/PATCH/DELETE，且用户已登录、非 `/auth/` 路径

- 记录内容：trace\_id（响应头 `x-trace-id` 回显）、模块（由路径推断：users→用户管理等）、操作类型（POST→CREATE 等）、请求方法/地址/参数、响应状态与 JSON 响应体、IP、UA、耗时

- **脱敏**：键名匹配 `password/token/secret/authorization`（忽略大小写）的值替换为 `******`，递归处理嵌套

- 特殊处理：AI 流式接口不包装响应（避免缓冲破坏流式）；multipart 请求不缓存请求体；查询串手动解析（规避 Tomcat 流消费问题）

### 权限校验（@RequirePermission）

方法级注解，多个权限满足任一即可；JWT 中 roles 含 `admin` 直接放行；否则查库比对用户实际拥有的权限标识集合，不通过返回 403 FORBIDDEN。

## 八、遗留说明

- 原 `user` 表演示接口（User/Hello 相关）全部保留，不受迁移影响

- 登录限流仅在激活 `prod`/`production` profile 时生效（与 Express 的 NODE\_ENV=production 行为一致）

- AI 流式接口客户端断连时会终止上游转发（SSE 连接随 try-with-resources 关闭）

- JWT secret 与 AI Key 为敏感信息，生产环境建议通过环境变量注入
